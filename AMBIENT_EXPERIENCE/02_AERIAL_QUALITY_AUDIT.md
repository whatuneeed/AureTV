# Aerial Quality Audit — Apple screensaver catalogue

**Дата аудита:** 2026-11-17  
**Источник:** [Google Sheets — Apple TV Aerials](https://docs.google.com/spreadsheets/d/1bboTohF06r-fafrImTExAPqM9m6h2m2lgJyAkQuYVJI)  
**Данные:** публичный XLSX-экспорт; лист `All Aerials`, скрытый лист `Links` с прямыми ссылками.  
**Каталог проекта:** `app/src/main/assets/aerial_catalog.json`.

## Короткий вывод

- Сейчас в каталоге **100 клипов**, и каждый хранит **один** `videoUrl`: 1080p H264. Модель `AerialClip` не умеет выбирать качество.
- В таблице **203 строки клипов**; из них **135** имеют полный набор `1080p / 1080p HDR / H264 / 4K / 4K HDR`, **160** — H264, **152** — 240p.
- **75 из 100** текущих клипов точно сопоставляются с таблицей и имеют **все шесть вариантов**. Это реальная база для quality-aware Aerial.
- **25 из 100** текущих клипов не имеют вариантов в таблице. В основном это India/новые ролики; для них таблица даёт только 240p или не содержит строки. Их нельзя «улучшить» без отдельного источника.
- Проверено **549 уникальных URL** (100 текущих + 449 уникальных вариантов 75 сопоставленных клипов): все ответили `HTTP 206` на Range GET 1 байт. Мёртвых ссылок в кандидатах нет.
- В таблице **46 ссылок на `phobos.apple.com`** — исторические; их нельзя использовать без расширения cleartext-исключения. В кандидатах они не использованы.
- **HDR/4K не проверены на физическом ТВ.** Таблица не указывает HDR-формат (HDR10/HLG/Dolby Vision); бейдж HDR нельзя показывать до проверки декодера и панели.

## 1. Что именно есть в таблице

Таблица содержит не один список, а матрицу вариантов:

| Колонка | Значение |
|---|---|
| `1080p` | 1080p HEVC SDR |
| `1080p HDR*` | 1080p HEVC HDR |
| `1080p H264` | 1080p AVC SDR, самый совместимый |
| `4K` | 2160p HEVC SDR |
| `4K HDR*` | 2160p HEVC HDR |
| `240p` | низкое качество/fallback |
| `Notes` | `dead link`, длина, перецвет, дефект, remastered |

`*` — формат HDR в таблице не раскрыт. Это не доказательство HDR10/HLG/DV.

### Ссылки

- Всего уникальных URL: **833**.
- `sylvan.apple.com`: **787**.
- `phobos.apple.com` / `a1.v2.phobos...`: **46**.
- В таблице **51 строка** с пометкой `dead link`; часто это старые `1080p`/`HDR`-ссылки, а рядом есть живая remastered-строка (`4a`, `1a` и т.п.).
- Поэтому нельзя просто взять первую строку по названию: нужно выбирать живую remastered-строку.

## 2. Сопоставление с текущим каталогом

Сопоставление сделано по имени файла видео (не по названию локации): текущий H264-файл ищется в `Links`/`All Aerials`. Это важно, потому что таблица использует другие каталоги и иногда другие названия.

| Результат | Клипов |
|---|---:|
| Всего в текущем каталоге | 100 |
| Сопоставлено и есть все шесть вариантов | **75** |
| Не сопоставлено / нет вариантов | **25** |

Для **75** сопоставленных клипов доступны:

- `1080p` — 75
- `1080p HDR` — 75
- `1080p H264` — 75
- `4K` — 75
- `4K HDR` — 75
- `240p` — 75

Все 75 H264-ссылок и все 75 вариантов каждого качества — на `sylvan.apple.com`.

### 25 клипов без вариантов

Это не «мёртвые» клипы: их текущие H264 URL живые. Просто таблица не даёт для них 4K/HDR/1080p-вариантов:

`Goa Beaches`, `Through Himalayas`, `Tea Gardens from Above`, `California’s Temblor Range`, `Redwoods from Above`, `Utah Evening`, `California’s Carrizo Plain`, `Goa Coast`, `Redwoods River`, `Arizona’s Coal Mine Canyon`, `Himalayas Day`, `Utah’s Lake Powell`, `Oregon Sunset`, `Utah’s Cathedral Canyon`, `Utah’s Olympia Bar`, `Oregon Coastline`, `The Ganges`, `California Wildflowers`, `Ghansali from Above`, `Utah’s Monument Valley`, `Utah’s Factory Butte`, `Tea Gardens Day`, `Reservoir Day`, `Himalayan Peaks`, `Tea Gardens Mist`.

Для них в таблице в основном только 240p или строки нет. Оставляем текущий H264 без обещаний 4K/HDR.

## 3. Проверка ссылок

Проверка выполнялась не из приложения, а отдельным аудитом:

- URL: `http://sylvan.apple.com/...` (как в текущем Aerial; HTTPS-сертификат Apple не проходит на части ТВ).
- Метод: `Range: bytes=0-0`, ожидался `206 Partial Content`.
- Проверено: **549** уникальных URL.
- Результат: **549 / 549 — HTTP 206**, ошибок нет.

Это доказывает доступность файлов, но **не** доказывает, что конкретный телевизор декодирует HEVC/HDR/4K. Это отдельная проверка.

## 4. Что можно включать

### Безопасно и полезно уже сейчас

1. **1080p HDR / H264 / 1080p SDR** для 75 клипов — при условии проверки HDR-формата.
2. **240p** — только как fallback при плохой сети, не как основной режим.
3. **4K SDR** — как opt-in для панелей/декодеров, которые реально это тянут; не включать по умолчанию.
4. **4K HDR** — только после физического теста; пока не показывать бейдж HDR и не обещать его.

### Чего не делать

- не использовать `phobos.apple.com` без отдельного решения по cleartext;
- не брать строки с `dead link`;
- не считать, что наличие 4K-файла означает поддержку 4K на ТВ;
- не подменять 25 клипов без вариантов выдуманными 4K/HDR-ссылками;
- не тянуть Google Sheets в runtime; это одноразовый аудит, а не зависимость приложения.

## 5. Предлагаемая реализация Stage 2

1. Добавить `AerialVariant`:
   `url`, `width`, `height`, `codec`, `hdr`, `label`.
2. Сохранить обратную совместимость: старый `video` = 1080p H264 SDR.
3. Чистая политика выбора:
   `4K HDR → 4K SDR → 1080p HDR → 1080p H264 → 240p`.
4. Откат на следующий вариант при ошибке плеера; не более одного прохода, без бесконечного retry.
5. Настройка качества в Aerial (в реализации — `1080p (совместимо)` / `4K/HDR`); новый ключ провести через backup/restore.
6. Показывать качество и «HDR недоступен» честно; HDR-бейдж только после физического теста.
7. Не кэшировать 4K целиком; текущий Aerial стримит, это сохранить.

## 5a. Статус Stage 2 (реализовано)

- `AerialVariant` (`label/url/width/height/codec/hdr`) и `variants` в bundled-каталоге: **92** клипа (75 исходных + 17 добавленных на Stage 3).
- `AerialQualityPolicy` — чистый выбор `compatible` (1080p H264) или `best`:
  `4K HDR → 4K SDR → 1080p HDR → 1080p HEVC → 1080p H264`; шаг пропускается, если панель/декодер не подтвердили UHD/HEVC/HDR. 240p не используется как основной режим.
- `AerialDeviceCapabilities` читает физический режим дисплея, HDR10/HLG и наличие HEVC-декодера; при сомнении остаётся 1080p H264.
- `SaverScreen` делает **один** проход по цепочке при ошибке; сеть не кэшируется, бесконечного retry нет.
- Settings: тумблер `1080p (совместимо)` / `4K/HDR`, честная строка «1080p (ТВ без 4K/HDR)», если панель не заявляет 4K/HDR.
- Backup/restore: новый ключ `ambient_aerial_quality` (`compatible`/`best`), старые архивы → `compatible`.
- Тесты: `AerialQualityTest` (8), `AerialCatalogTest` (варианты + refresh + реальные кадры), `BackupCodecTest` (поле), `SaverPreviewTest` (bundled-кадр). **Физический 4K/HDR ТВ по-прежнему NOT TESTED.**

## 5b. Статус Stage 3 (реализовано)

- Каталог: **117** клипов (было 100). Добавлены 17 реальных Apple Aerial, каждый — уникальный клип, не альтернативная версия существующего (проверены id, файл, `accessibilityLabel`).
- Все 17 имеют живой 1080p H.264 (`sylvan.apple.com`, HTTP 206) и полный набор вариантов из старой официальной таблицы: `1080p`, `1080p_hdr`, `h264`, `4k`, `4k_hdr`. Проверено **85/85** URL (17 клипов × 5 рендишенов), все ответили 206.
- У 17 клипов **нет официального `previewImage`** (Apple убрала картинки из старой ленты). Поэтому превью — **реальный кадр из видео этого же клипа**, снятый на 5 с (для серых рифовых акул — на 25 с, где видны акулы), приведённый к 900×580 JPEG q82. Это не рисунок и не чужой кадр.
- Кадры лежат в `app/src/main/assets/aerial_previews/<asset-id>.jpg`; в каталоге `preview` = `asset:aerial_previews/<asset-id>.jpg`. `AerialPreviewStore` читает `asset:` без сети, кладёт байты в тот же кэш и не ходит на CDN за превью.
- Названия: EN — официальные `accessibilityLabel`/таблицы; RU — авторские переводы. Темы: Природа +3, Города +4, Планета Земля +3, Под водой +7.
- Проверка на AVD: «Ролики» показывает `117 из 117`; новые кадры отображаются в сетке (выборочно проверены `Эмбаркадеро`, `Озеро в Шотландии`, `Рыбы-попугаи`, `Коровьи скаты`, `Серые рифовые акулы`, `Лес водорослей`, `Кораллы Красного моря`, `Морские звёзды`, `Медузы Палау II`).
- Тесты: `AerialCatalogTest` (117, 92 с вариантами, 17 `asset:`-превью), `SaverPreviewTest` (bundled JPEG 900×580 грузится без сети); targeted unit + instrumented прошли.
- Ограничение: это по-прежнему **не официальные Apple preview PNG**; при появлении официального `previewImage` его следует предпочесть. Кадры — производные кадры Apple Aerial, права принадлежат Apple; юридическая проверка распространения в APK не проводилась. Физический 4K/HDR ТВ и HEVC-декодер не тестировались.

## 6. Ограничения аудита

- **Физический 4K/HDR ТВ не тестировался.**
- **Формат HDR не определён** — таблица пишет только `HDR`.
- **Декодирование HEVC Main10 / HDR10 / HLG / DV не проверялось.**
- **ARM32/64, 1 GB RAM, 720p/4K панель** — не проверялись.
- **Превью-картинки**: сетевые Apple previews в аудите не проверялись; 17 локальных кадров проверены инструментально и на AVD.
- Названия в таблице и каталоге иногда расходятся; сопоставление по файлу надёжнее, но требует ручной проверки при добавлении новых клипов.

## Артефакт

Машиночитаемое сопоставление: `AMBIENT_EXPERIENCE/aerial_quality_map.json`.

Оно содержит 75 сопоставленных клипов с вариантами и 25 клипов без вариантов; 17 клипов Stage 3 добавлены с вариантами из той же старой официальной таблицы, но в машиночитаемую карту не входят. Это **не runtime-ассет** и не должно попадать в APK без отдельного решения.
