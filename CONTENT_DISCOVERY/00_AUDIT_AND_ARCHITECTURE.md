## A3. Подсистема рекомендаций сегодня — как устроена

1. `HomeScreen` вычисляет `shelfApp` — приложение под курсором **дока**.
2. `LaunchedEffect(shelfApp.packageName, resumeTick)` вызывает `WatchNextSource.load(context, packageName, includeContinue)` (`HomeScreen.kt:401–420`).
3. `WatchNextSource` делает два запроса (`WatchNextPrograms` + устаревший `PreviewPrograms`) с `selection = package = ?`, читает до 500 строк, строит `WatchNextRow`, затем `rankWatchNext`:
   - оставляет только строки этого пакета;
   - требует непустые `title` и `intentUri`;
   - фильтрует continue-строки по настройке;
   - сортирует по `LAST_ENGAGEMENT_TIME_UTC_MILLIS` убыв.;
   - дедуплицирует по intent;
   - ограничивает 6 карточками (`MAX_CARDS`).
4. `TopShelf` показывает выбранную карточку на весь экран, точки-переключатели, название/эпизод/прогресс.
5. OK: `WatchNextSource.contentIntent` парсит intent, проверяет, что он резолвится **в тот же пакет**, и запускает.
6. Если строк нет — показывается баннер приложения, иначе пусто.

### Что это даёт и чего не даёт

- Это **реальные** данные: строки публикует само приложение через `TvContract`. Лаунчер не читает чужие БД, не парсит сервисы, не обходит авторизацию.
- Это **app-specific рекомендации** в чистом виде — требование «при выборе приложения показать относящийся к нему контент» уже выполнено архитектурно.
- Нет **межприложенческого** Continue Watching: строки других приложений отбрасываются фильтром пакета.
- Нет «Recommended for You», «Recently Used», «Favorites», «Trending» как сущностей.
- Нет истории запусков, счётчиков, избранного, скрытия рекомендаций, причин рекомендации.
- Ранжирование — один сигнал (`engagement`) без затухания, разнообразия и защиты от повторов.

## A5. Изображения

- Провайдерные строки: `THUMBNAIL_URI` (обычно 16:9) и `POSTER_ART_URI` (2:3); `ShelfCard.artUri = thumbnailUri ?: posterUri` (`WatchNext.kt:23`), т. е. **для полноэкранного героя предпочитается thumbnail**, а не постер.
- Декодирование: bounds-first, `inSampleSize` до `shelfArtMaxPx`, `RGB_565`, лимит 8 MiB, таймауты 10 с, memory-LRU на 12 записей (`TopShelf.kt:386–600`).
- `AdaptivePolicy`: `shelfArtMaxPx` = **1280** на HIGH/BALANCED, 960 на LOW (`AdaptivePolicy.kt:70,81,90`), независимо от разрешения панели.
- Сетка: баннер 400×240 (1080p) / 500×300 (≥2560 px), иконка 256 (`AppRepository.kt:164`).
- Баннер приложения для героя декодируется в 1920×1080 и только если источник не меньше 1/2 цели (`bannerIsHero`).
- Кэши: `AppArtCache` (KB-бюджет), `shelfArtCache` (12 записей), `AerialPosterStore`; `MemoryPressure` уменьшает `maxSize`, а не только `trimToSize` (AQ-15 исправлен).
- Диск-кэша изображений нет (провайдер/APK — источник), JSON-кэши есть у погоды/заставки.

**Вывод по 4K:** на панели 3840 px герой 1280 px растягивается примерно в 3 раза по ширине. Это не «4K-качество», а апскейл. Источник правды — провайдер: если он отдаёт только 1280×720, честный путь — не растягивать на весь экран, а показывать крупную карточку/постер с фоном, либо ограничить герой и явно не заявлять 4K. Отдельных миниатюр и полноразмерных вариантов с разными ключами кэша сейчас нет: один URI → один декод.

## A6. Навигация и фокус

- Собственный D-pad-движок; `TvCanvas` + safeDrawing; `FocusRequester` на плитку/строку; фокус профиля сохраняется (`KEY_FOCUS_PACKAGE`, `KEY_SHELF_PACKAGE`).
- Dock → Up: полка (если есть карточки) или статус-пилюля (если нет) (`HomeScreen.kt:1152–1170`).
- Полка: Left/Right — карточки, Down/Back — возврат в док, Up — пилюля, OK — запуск (`HomeScreen.kt:1096–1140`).
- Смена приложения дока сбрасывает `shelfFocus = -1`, `shelfSelected = 0` и перезагружает карточки.
- Возврат из запущенного приложения: `resumeTick` перезагружает полку, но **не сбрасывает** выбранную карточку (кроме случая, когда карточек стало меньше).
- Секций нет, поэтому нет и восстановления позиции между секциями.

## A7. Ошибки и состояния

| Ситуация | Текущее поведение | Оценка |
|---|---|---|
| Нет разрешения `READ_TV_LISTINGS` | Пустая полка/баннер | Нет объяснения пользователю на Главной |
| Рекомендации выключены | Пустая полка/баннер | Не отличимо от «нет данных» |
| Провайдер вернул 0 строк | Баннер приложения | Корректный fallback |
| Провайдер бросил исключение | `runCatching` → пусто, без диагностики | Молчаливое проглатывание |
| Строка с битым intent | Показывается; проверка только при нажатии | «Мёртвая» карточка |
| Приложение удалено, строка осталась | Строка показывается до перезагрузки/нажатия | Нет фильтра установленности |
| Нет интернета | На полку не влияет (локальный провайдер) | Корректно; для будущих сетевых источников кэш нужен |
| Устаревшие данные | Понятия нет | Для провайдера неактуально, для сети — будет нужно |
| Нет изображения | Пустой герой/баннер | Нет нейтральной карточки с названием и источником |

Сетевые таймауты/backoff есть только у арта полки. Для провайдера они не нужны (локальный ContentProvider), для будущих API — обязательны.

## A8. Что можно и нужно переиспользовать

1. `WatchNextSource` — оставить как **провайдерный источник**, расширив выборку на все пакеты и добавив фильтр установленности.
2. `rankWatchNext` — оставить как частный случай ранжирования; новые веса не должны его ломать.
3. `TopShelf` art pipeline (bounds-first, лимиты, LRU, epoch, `MemoryPressure`) — основа для карточек любых секций.
4. `TvOs`, `TvTokens`, `TvCanvas`, `CardShell`, `AppCard`, `FocusRequester`-паттерн — визуальный слой уже есть.
5. `ProfileStore.homePrefsName(id)` — готовый механизм профильного хранения.
6. `KidsMode.kidsFilter` — обязательный фильтр для любых рекомендаций в Kids.
7. `AdaptivePolicy` — единственное место бюджетов; новые кэши добавляются туда.
8. `PackageChange` receiver + `resumeTick` — готовые точки инвалидирования.
9. `WatchNextTest` / `TopShelfTest` — база для тестов движка.

## A9. Ограничения, которые нельзя «исправить» кодом

- Лаунчер **не имеет** доступа к истории просмотров внутри сторонних приложений. Единственный санкционированный канал — строки, которые приложения сами опубликовали в `TvProvider`.
- `READ_TV_LISTINGS` не даёт доступа к каталогам Netflix/YouTube/Кинопоиска/Twitch. Публичных каталогов у них нет (раздел D).
- `HdmiControlManager`, `MediaSessionManager.getActiveSessions` и чужие БД требуют системных прав/согласия — вне scope.
- Названия строк провайдера и их арт — ответственность приложения; лаунчер не может улучшить их «бесплатно» и не должен подменять выдуманными данными.
- Kids Mode — локальная защита поверхностей лаунчера, не Android parental control.

# B. Content Discovery Architecture

## B1. Принципы

1. **Не создавать вторую систему.** `WatchNextSource` остаётся единственным читателем `TvProvider`; новый движок — надстройка, а не замена.
2. **Один владелец состояния.** Снапшот рекомендаций принадлежит профилю; UI только отображает.
3. **Источник — часть модели.** У каждой карточки есть `sourceId` и `reason`; карточка без проверяемого источника не создаётся.
4. **Честные пустые состояния.** Нет данных → секция отсутствует; нет разрешения → подсказка, а не «рекомендации».
5. **Никаких секретов в APK.** Внешние API — только с пользовательским ключом; v1 работает без них.
6. **Сначала правила, потом ML.** Прозрачная формула; ML не внедряется без данных и необходимости.
7. **Расширяемость без переписывания.** Новый источник = реализация интерфейса + регистрация; UI не меняется.

## B2. Модули (пакет `com.whatuneed.ovisiontv.kotlin.discovery`)

```text
discovery/
  DiscoveryModels.kt      чистые модели, enum'ы, ArtRefs, LaunchRef, SourceState
  DiscoverySource.kt      интерфейс источника + SourceStatus/Availability
  ProviderRowsSource.kt   TvProvider (обёртка WatchNextSource, все пакеты)
  LauncherUsageSource.kt  история запусков + избранное (локально)
  AppCatalogSource.kt     установленные приложения как карточки (Recent/Favorites)
  DiscoveryStore.kt       профильное JSON-хранилище сигналов и снапшотов
  DiscoveryCache.kt       in-memory + диск, TTL, stale, версия схемы
  DiscoveryRanking.kt     чистые функции: score, diversity, caps, reasons
  DiscoveryEngine.kt      оркестрация: sources → candidates → rails → snapshot
  DiscoverySettings.kt    профильные переключатели, миграция, clear()
```

Зависимости: только `android.content`, `org.json`, `kotlinx.coroutines`, существующие `data`-классы. Никаких новых Gradle-зависимостей.

## B3. Модель данных

```kotlin
enum class DiscoverySectionId { CONTINUE, FOR_YOU, FROM_APP, RECENT, FAVORITES }
enum class DiscoveryKind { MOVIE, SERIES, EPISODE, LIVE, GAME, APP, MUSIC, UNKNOWN }
enum class DiscoveryReason {
    CONTINUE_WATCHING, RECENTLY_LAUNCHED, FAVORITE, NEW_FROM_APP,
    OFTEN_USED, FROM_CURRENT_APP, DIVERSE_PICK,
}
enum class DiscoverySourceId { TV_PROVIDER, LAUNCHER, PACKAGE_MANAGER }

enum class ArtRole { HERO, CARD }

data class ArtRef(val uri: String, val widthPx: Int?, val heightPx: Int?)

data class ArtRefs(
    val landscape: ArtRef?,   // THUMBNAIL_URI или баннер приложения
    val poster: ArtRef?,      // POSTER_ART_URI
) {
    fun bestFor(role: ArtRole): ArtRef?   // выбор по пропорции и площади, не «первый непустой»
}

data class LaunchRef(
    val intentUri: String?,          // provider intent://
    val packageName: String,
    val activityName: String?,       // для приложений
)

data class DiscoveryItem(
    val id: String,                  // стабильный ключ: source + providerId/intentUri/package
    val source: DiscoverySourceId,
    val kind: DiscoveryKind,
    val packageName: String,
    val title: String,
    val subtitle: String?,
    val art: ArtRefs,
    val launch: LaunchRef,
    val progress: Float?,
    val lastEngagementUtc: Long?,
    val reason: DiscoveryReason,
    val score: Double,
)

data class DiscoveryRail(
    val id: DiscoverySectionId,
    val items: List<DiscoveryItem>,
    val stale: Boolean = false,
)

data class DiscoverySnapshot(
    val profileId: String,
    val rails: List<DiscoveryRail>,
    val generatedAtUtc: Long,
    val sources: Map<DiscoverySourceId, SourceState>,
)

enum class SourceState { OK, EMPTY, NO_PERMISSION, DISABLED, FAILED, STALE }
```

`kind` выводится **только** из доступных полей провайдера (`SEASON_DISPLAY_NUMBER`, `EPISODE_DISPLAY_NUMBER`, `ITEM_COUNT`, длительность, тип строки). Жанры, рейтинги и «похожее» не выдумываются: если полей нет — `UNKNOWN`, и карточка группируется по приложению.

## B4. Конвейер

```text
resume / package change / profile switch / manual refresh
        │  (debounce 500 ms, IO)
        ▼
DiscoveryEngine.refresh(profileId)
  ├─ AppCatalogSource: установленные пакеты + leanback-флаг (один проход PM)
  ├─ ProviderRowsSource: одна выборка всех строк (если разрешение и тумблер)
  ├─ DiscoveryStore: usage, favorites, hidden, lastShown
  ├─ buildCandidates(): дедуп по id/intent, фильтр installed/hidden/kids
  ├─ validateLaunch(top-N): resolve intent/component (кэш на сессию)
  ├─ DiscoveryRanking:
  │     score → sort → diversity → per-rail caps → thresholds
  ├─ omit empty rails (< minItems, кроме CONTINUE)
  ├─ persist lastShown + snapshot (JSON)
  ▼
DiscoverySnapshot (immutable) → Compose state (Main)
        │
        ▼
TopShelf(sections, selectedSection, focus) — только выбранная секция
```

Пересборка не запускается на каждое движение фокуса. Фокус меняет только `selectedSection`/`focusedIndex`; данные неизменны до `resumeTick`/package event/TTL.

## B6. Кэширование и обновление

| Слой | Что | Политика |
|---|---|---|
| Снапшот в памяти | `DiscoverySnapshot` | Живёт до смены профиля/пакета/`resumeTick`+TTL (5 мин для провайдера) |
| Диск | JSON снапшота профиля | Атомарная запись (`AtomicWrite`), версия схемы, максимум 64 КБ |
| Провайдер | не кэшируется отдельно | Локальный запрос дешевле диска; снапшот — уже кэш |
| Арт | memory-LRU по ключу `uri|targetPx|role` | Байтовый бюджет, `MemoryPressure`, epoch |
| Внешние API (позже) | метаданные по id | TTL 7 дней, max 200 записей, ETag, без дискового кэша изображений |
| Инвалидация | `resumeTick`, `PACKAGE_ADDED/REMOVED/CHANGED`, смена профиля, ручное обновление | Debounce 500 мс, generation-проверка перед публикацией |

Устаревший снапшот показывается с `stale = true` только если источник временно недоступен; для `TvProvider` это практически не случается. Устаревшие строки не выдаются за свежие.

## B8. Профили и приватность

- Все сигналы и снапшоты — в `ProfileStore.homePrefsName(profile.id)`; p1 сохраняет существующий файл, миграция не нужна.
- `DiscoverySettings(profileId)`: `personalization` (default on), `recommendations`, `continueWatching`, `clearHistory()`, `hidden()`.
- При первом чтении профиля без ключей — наследовать текущее глобальное значение p1 (однократная миграция), дальше писать только профильный ключ.
- Kids-профиль: межприложенческие секции **выключены**; показываются только строки разрешённых приложений (как сегодня). История Kids не влияет на взрослые профили.
- Не собираются: имена, аккаунты, содержимое просмотров, геолокация, IMEI, рекламные id. Хранятся только package, id строки, intent, timestamp, счётчик.
- Персонализация off → движок отдаёт нейтральные секции: Continue Watching из провайдера + «Из ваших приложений» (без истории).
- «Очистить историю рекомендаций» удаляет usage/favorites/hidden/lastShown/снапшот профиля; настройки и разрешение не трогаются.

## B9. Состояния и ошибки

| Состояние | UI | Данные |
|---|---|---|
| Загрузка | Скелетон-полка без прыжка layout (фиксированная высота) | старый снапшот, если есть |
| Успех | Секции с карточками | свежий снапшот |
| Нет рекомендаций | Секция отсутствует; баннер приложения (как сейчас) | пустой снапшот |
| Нет разрешения | Баннер + строка «Включить рекомендации» в настройках | `NO_PERMISSION` |
| Нет интернета | Не влияет на провайдер; для будущих API — stale-снапшот | `STALE` |
| Источник недоступен | Секция скрыта, остальные работают | `FAILED` |
| Ошибка авторизации (будущие API) | Секция скрыта, строка в настройках «Ключ не принят» | `FAILED` |
| Источник больше не поддерживается | Секция скрыта, запись в настройках | `DISABLED` |
| Устаревшие данные | Показ с пометкой давности только в деталях, не на карточке | `STALE` |
| Приложение удалено | Карточки и секция фильтруются при сборке | фильтр installed |
| Нет изображения | Нейтральная карточка: название + иконка/бейдж приложения, без выдуманного арта | `art = null` |

Ошибка одного источника не ломает снапшот: `DiscoveryEngine` собирает секции из того, что доступно, и возвращает `SourceState` для настроек/диагностики.

## B10. Производительность

- Провайдерный запрос — один раз на refresh, не на фокус; `MAX_ROWS` сохраняется, но обработка — O(n) без повторных `getColumnIndex`.
- Валидация intent — только для топ-N карточек каждой секции (≤ 24 resolve), кэшируется на сессию.
- Ранжирование — чистые функции на `Dispatchers.Default`; публикация — на Main.
- Compose: immutable `DiscoverySnapshot`, `key(item.id)`, отдельные состояния для `selectedSection`/`focusedIndex`; смена фокуса не пересобирает снапшот.
- Арт: префетч только текущей секции (±2 карточки), не всех секций; отмена при уходе; `MemoryPressure`/`Adaptive` уже есть.
- Никакого Main I/O и никаких полных перезагрузок экрана при изменении одной карточки.

# C. Recommendation Engine

## C1. Сигналы

| Сигнал | Источник | Достоверность | Ограничение |
|---|---|---|---|
| Continue (прогресс/тип строки) | `TvProvider` | Высокая | Только если приложение публикует |
| Engagement (время последнего взаимодействия) | `TvProvider` | Высокая | Может быть 0 у части приложений |
| Запуски приложения из лаунчера | локально | Высокая (наши данные) | Не равно просмотру |
| Избранное | локально, явно | Высокая | Пользователь должен явно добавить |
| Скрытое | локально, явно | Высокая | Жёсткий фильтр |
| Профиль/Kids | локально | Высокая | Ограничивает набор |
| «Популярное/тренды» | нет источника | — | Не имитировать |

## C2. Формула (прозрачная, без ML)

Все сигналы нормализуются в 0..1, веса — в одном объекте `DiscoveryWeights`:

```text
score =
  0.35 * continue          // есть прогресс/тип CONTINUE — 1.0, иначе 0
+ 0.20 * recency           // exp(-ageDays / 14), age от engagement/запуска
+ 0.15 * affinity          // log1p(launches_30d) / log1p(max_launches), 0..1
+ 0.10 * favorite          // 1.0 для избранного
+ 0.10 * inCurrentApp      // карточка принадлежит приложению под курсором
+ 0.10 * sourceConfidence  // TV_PROVIDER 1.0, LAUNCHER 0.8, PACKAGE 0.7
- 0.25 * recentlyShownPenalty   // 1.0 сразу после показа, линейно к 0 за 7 дней
- 0.10 * samePackageRank        // 1.0 для второй карточки того же пакета, 0.5 для третьей
```

- `recency`: `engagement` строки провайдера; для приложений — последний запуск.
- «Новое в приложении» — высокий `recency`, но не `continue`; отдельная причина `NEW_FROM_APP`.
- Порог: карточка попадает в секцию при `score >= 0.25`. Секция показывается при ≥ 3 карточках (CONTINUE — при ≥ 1).
- Все константы вынесены и покрыты тестами; изменение веса не требует правок UI.

## C3. Разнообразие и защита от повторов

1. **Квота на пакет:** не более 2 карточек одного приложения в секции (кроме `FROM_APP`, где это единственная тема).
2. **Категорийный баланс:** не более 60% одной категории (`EPISODE`/`MOVIE`/`APP`), если есть альтернативы.
3. **Дневная ротация:** tie-break по `hash(profileId, epochDay, itemId)`; внутри дня порядок стабилен, на следующий день меняется — без «мельтешения» при каждом resume.
4. **Штраф за недавний показ:** `lastShown` хранит до 32 id на секцию с timestamp; повторный показ не запрещён (это может быть любимый контент), но опускается ниже.
5. **Квота исследования:** 1 слот из 7 отдаётся лучшему кандидату, чей пакет не запускался 30 дней и `score >= 0.35`; причина `DIVERSE_PICK`. Это расширяет кругозор, не игнорируя предпочтения.
6. **Никакой бесконечной ленты:** максимум 4 секции, максимум 8 карточек в каждой, один герой.

## C4. Профили

- Данные не смешиваются: ключи профиля, `profileId` в снапшоте, при смене профиля снапшот пересобирается, кэш арта общий (обезличенные URI), но `lastShown` — профильный.
- Kids: только allowlist; межприложенческие секции не строятся; история Kids не читается взрослыми профилями.
- Явные предпочтения: избранное, скрытие, тумблер персонализации, очистка истории — в настройках профиля.
- Удаление профиля → `DiscoveryStore.clear(profileId)` (вызывается из `ProfileStore.delete`).

## C5. Холодный старт

Нет истории → «Продолжить просмотр» из провайдера (если есть), «Из ваших приложений» по установленным приложениям с опубликованными строками, «Недавние» отсутствует. Никаких «популярных фильмов» без источника. Первый экран не должен выглядеть пустым: остаётся dock и баннер приложения.

## C6. Почему не ML

Нет истории лаунчера, нет идентификаторов контента, нет объёма взаимодействий; провайдерные строки разрежены и не содержат жанров. Обучение на таких данных даст шум и непроверяемые рекомендации. Правила прозрачны, тестируемы и объяснимы; ML — отдельный этап при появлении ≥ 10⁴ взаимодействий и легального каталога.

## C7. Объяснимость

Каждая карточка несёт `reason`; UI показывает короткую причину:
- «Продолжить с 42 мин» — `CONTINUE_WATCHING`;
- «Недавно открывали» — `RECENTLY_LAUNCHED`;
- «В избранном» — `FAVORITE`;
- «Новое в приложении» — `NEW_FROM_APP`;
- «Вы часто открываете это приложение» — `OFTEN_USED`;
- «Из Netflix» — `FROM_CURRENT_APP`;
- «Попробуйте что-то новое» — `DIVERSE_PICK`.

Причина не выдумывается: если сигнала нет, карточка не получает причину и не показывается в персональной секции.

# E. Visual Experience

## E1. Модель секций

Секции — это **рельсы внутри существующей полноэкранной полки**, а не новая бесконечная лента:

1. `CONTINUE` — «Продолжить просмотр»: строки с прогрессом/типом CONTINUE, все приложения.
2. `FOR_YOU` — «Для вас»: смесь провайдерных строк и приложений по весам; причина на карточке.
3. `FROM_APP` — «Из <App>»: текущее поведение, выбранное приложение под курсором дока.
4. `RECENT` — «Недавние»: приложения/контент, открытые из лаунчера.
5. `FAVORITES` — «Избранное»: явно добавленные карточки/приложения.
6. «Trending» — **не показывается**, пока нет легального источника. Вместо неё — «Новое в ваших приложениях» (провайдерные строки с высоким recency), если данных достаточно.

Правила: секция отсутствует, если карточек меньше порога; одновременно видна одна секция; максимум 4 секции в снапшоте; точки-пагинация заменяются компактным section strip + горизонтальной рельсой.

## E2. Варианты UI (нужно выбрать)

**Вариант A (рекомендуется) — «Sectioned Shelf».**
- Up с дока открывает полку; сверху — компактные пилюли секций (только непустые), ниже — заголовок и горизонтальная рельса крупных карточек, выбранная карточка становится полноэкранным героем (существующий crossfade).
- Левая/правая — карточки; Up с первой карточки — секции; Down/Back — док; OK — открыть; долгое OK — меню «Избранное/Скрыть/Открыть».
- Плюсы: соответствует требованию «горизонтальные подборки», все секции доступны без новой навигации, сохраняется tvOS-минимализм (одна секция за раз).
- Минусы: меняет текущую parade-полку (точки), нужны новые UI-тесты.

**Вариант B (минимальные изменения) — «Section tabs + parade».**
- Сохраняются точки и один герой; добавляется только strip секций. Секция = тот же карусельный парад.
- Плюсы: меньше кода и риска. Минусы: нет «горизонтальной подборки» как визуального объекта, хуже обзор.

Рекомендация: **A**. Вариант B — запасной, если важнее сохранить текущую полку без изменений.

## E3. Карточки, пропорции, арт

| Роль | Размер (design pt, 1920×1080) | Источник | ContentScale |
|---|---|---|---|
| Hero | на весь экран | landscape (thumbnail/баннер) | Crop, но только если источник ≥ 1/2 цели |
| Rail card (16:9) | 440×248 | landscape | Crop |
| Rail card (2:3) | 320×480 | poster | Crop |
| App card (Recent) | 250×150 | баннер приложения | существующий `AppCard` |

- Пропорция карточки определяется доступным артом: 16:9 для эпизодов/continue/приложений, 2:3 для фильмов/сериалов с постером. Не растягивать.
- Если есть только постер, а карточка 16:9 — использовать `ContentScale.Crop` с фокусом по центру; не «растягивать» и не добавлять выдуманные поля.
- Нет арта — нейтральная карточка: название + бейдж приложения; герой — фон-градиент, не чужой постер.
- Бейдж источника (иконка/название приложения) на карточках межприложенческих секций; в `FROM_APP` он избыточен.

## E4. 4K и качество

- Цель декода вычисляется от **физической ширины панели** и бюджета, а не от константы:
  - `HERO`: HIGH 2560, BALANCED 1920, LOW 1280 px;
  - `CARD`: HIGH 720, BALANCED 640, LOW 480 px.
- `inSampleSize` — по bounds; `inScaled = false`; `RGB_565` для карточек; `ARGB_8888` для героя только на HIGH и только если хватает бюджета (иначе `RGB_565`).
- **Запрет апскейла > 1.5×** по каждой оси: если источник меньше, герой не растягивается на весь экран; показывается карточка правильной пропорции на затемнённом фоне. Это честнее, чем «4K» из 1280 px.
- Ключ кэша: `uri|targetPx|role`; отдельные LRU для hero (1–2 записи) и карточек (8–12); байтовые бюджеты в `AdaptivePolicy`.
- `FilterQuality.Medium` только для героя; карточки — `Low`/`Medium` по замеру.
- Предзагрузка: текущая секция ± 2 карточки; при уходе — отмена/trim; `MemoryPressure` уже вызывает `trimShelfArtCache`.
- Не заявлять 4K, если источник меньше; в «О системе»/лицензиях — честная формулировка «качество зависит от источника».

## E5. D-pad и фокус

| Контекст | Up | Down | Left/Right | OK | Back |
|---|---|---|---|---|---|
| Dock | Полка (секция по умолчанию) | Сетка | Соседняя плитка | Запуск | — |
| Полка: секции | Статус-пилюля | Карточки | Смена секции | — | Док |
| Полка: карточки | Секции | Док | Соседняя карточка | Открыть | Док |
| Меню карточки | — | Пункты | Пункты | Действие | Закрыть |

- Секция по умолчанию: `FROM_APP` (если непустая) → `CONTINUE` → `FOR_YOU` → `RECENT` → `FAVORITES`; выбор запоминается на профиль.
- Позиция карточки запоминается **на секцию**; смена секции не сбрасывает позицию других.
- При обновлении снапшота фокус ищется по `item.id`; если элемент исчез — ближайший индекс в той же секции, иначе первая карточка, иначе док. Никаких прыжков в начало.
- Скролл рельса: `LazyRow` + `rememberLazyListState`, восстановление индекса без анимации при входе; анимация только при перемещении фокуса.
- Долгое OK: меню карточки; автоповтор пульта не должен открывать пункт сразу (паттерн `menuOpenedByHold` уже есть).
- TalkBack: секция — `contentDescription` с названием и количеством; карточка — название + причина + источник; strip — `selectable` semantics.

## J2. Отклонения от первоначального проекта

1. **Порог и «свежая» строка без timestamp.** Нейтральный `recencyFactor(null)` = 0.75, а не 0.4: иначе строка провайдера без `LAST_ENGAGEMENT_TIME` давала 0.18 и молча исчезала. Теперь 0.75 × 0.20 + 0.10 = ровно 0.25, порог проходит.
2. **Максимум секций — 4.** При пяти непустых рельсах убирается `RECENT`: Continue уже покрывает «недавнее», а избранное остаётся явным выбором.
3. **Kids.** В детском профиле остаются только `FROM_APP` и `CONTINUE`; строки разрешённых приложений видны, но `FOR_YOU`/`RECENT`/`FAVORITES` не строятся. Continue показывает реальную точку продолжения, а не рекомендацию.
4. **Нет отдельного `ArtRefs`.** Роль определяется в `TopShelf` (`ArtRole.CARD`/`HERO`), ключ кэша — `source:uri|targetPx|role`; апскейл запрещён: источник уже 2× ширины экрана не растягивается.
5. **Нет feature flag.** Пользовательский переключатель «Рекомендации» и есть флаг: OFF → пустой снапшот и прежний баннер приложения; старый путь не удалён.
6. **`SettingsScreen` разбит локальной `pageRows()`.** Гигантский composable упирался в лимит JVM 64 KB; вынесение `when (page)` в локальную `@Composable`-функцию сохранило поведение и сняло ошибку `Method too large`.
