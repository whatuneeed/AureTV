# 02 — Целевая информационная архитектура

Дата: 10.11.2026. Основание: `01_EXISTING_UI_AUDIT.md`. Это проектное решение, а не описание уже сделанного. Код не менялся.

---

## 1. Принципы

1. **Одна функция — одно основное место.** Дубли допустимы только как быстрый путь (Control Center, клавиши), но запись всегда одна.
2. **Не добавлять настроек ради структуры.** Мастер просит темы, обои, прозрачность, масштаб и размытие; владелец ранее отклонил темы и размытие, поэтому эти пункты **не вводятся**. Раздел «Интерфейс» наполняется тем, что реально существует: язык и заставка.
3. **Ни одного фиктивного переключателя.** Если функция не реализована — её нет в интерфейсе. Строка «Канал обновлений: Manual» удаляется, а не превращается в настройку.
4. **Пульт — основной вход.** Каждая поверхность имеет выход по BACK и предсказуемый возврат фокуса.
5. **Данные — из хранилища, а не из снимка.** Любое значение, которое может измениться в другом окне или мастере, перечитывается при возврате.
6. **Один визуальный язык.** Все поверхности собираются из токенов этапа 3; локальные литералы не допускаются.

---

## 2. Карта поверхностей (целевая)

Слойность сохраняется: это проверенная модель, менять её без причины нельзя.

```
LauncherRoot
├─ фон (градиент темы)
├─ HomeScreen
│  ├─ Top Shelf / hero
│  ├─ Dock
│  ├─ Grid / Library
│  ├─ FolderOverlay            (зум из плитки)
│  ├─ TvMenu: папка / приложение / перемещение
│  ├─ TvKeyboard (переименование)
│  ├─ SearchOverlay
│  ├─ ControlCenter
│  ├─ WeatherPanel
│  ├─ WeatherCapsule / StatusCapsule
│  └─ LaunchOverlay
├─ SaverScreen
├─ ProfilePicker
├─ PinPadOverlay
└─ SetupScreen (отдельная Activity)
```

Порядок слоёв не меняется: `Launch > PIN > Picker > Saver > (Home: CC/погода/поиск/меню/папка/сетка)`. Обоснование: PIN обязан быть выше всего, кроме запуска приложения; заставка — ниже любого модального запроса (закрыто в 0.4.35).

---

## 3. Контракт фокуса

Общий для всех поверхностей:

1. Открывая оверлей, экран запоминает владельца фокуса (плитка, капсула, строка).
2. Оверлей ставит фокус на свою первую смысловую цель (не на декоративную точку).
3. BACK закрывает оверлей и возвращает фокус владельцу; успешное действие возвращает фокус туда же, если поверхность осталась.
4. Диалог подтверждения возвращает фокус на строку, из которой открыт, а не в начало страницы.
5. После запуска приложения и возврата — фокус на запущенной плитке; после заставки — на прежней позиции.
6. После смены профиля — фокус на первой разрешённой плитке.
7. Ни один оверлей не оставляет фокус «в воздухе»: уход фокуса за пределы видимой области запрещён.

Требуют исправления: PIN-отмена (UX-08), повторное открытие папки (UX-09), декоративные точки полки (UX-11).

---

## 4. Контракт модальных запросов

- **PIN** — модальный запрос: заставка не идёт, таймер простоя перезапускается на обоих концах (сделано в 0.4.35), BACK = отмена без действия.
- **Детский профиль** — гейт распространяется на всё, что выводит за пределы разрешённого:
  - выход в системные настройки, специальные возможности и Bluetooth из Control Center (UX-01);
  - меню папки: удаление, сведения о приложении, вынос на Главную (UX-02);
  - смена профиля — уже закрыта PIN.
  Разрешённое ребёнку остаётся: запуск разрешённых приложений, поиск внутри разрешённого, погода, заставка, свой ярлык «Настройки» (он открывает PIN).
- **Разрешения** — каждая строка ведёт либо в собственную страницу «Разрешения», либо в системный экран; фиктивных запросов нет. Если действие недоступно на устройстве, строка честно заблокирована с пояснением, а не притворяется рабочей.

## 5. Навигация настроек (сводно)

Корень — 6 разделов. Подробная структура и маппинг — в `03_SETTINGS_STRUCTURE.md`.

```
Настройки
├─ Интерфейс        Язык · Заставка
├─ Главная          Рекомендации · Продолжение · Доступ к спискам · Скрытые · Сброс раскладки
├─ Профили          Список · Создать · Профиль (имя, аватар, детский, PIN, allowlist, удаление)
├─ Погода           Показ · Место · Единицы · Источник · Частота · Обновить
├─ Устройство       Сеть · Устройство · Хранилище · Разрешения · Система (запуск, дом, AirPlay)
└─ О системе        Обновления каталога · О системе · Лицензии и условия · Мастер настройки
```

Правила:

- «Общие» как раздел исчезает: язык — это интерфейс, а не «общее».
- «Главный экран» переименовывается в «Главная» (RU) / «Home» (EN) и остаётся единственным местом настроек Главной.
- «Заставка» переезжает внутрь «Интерфейса» (требование мастер-задачи §10), не теряя ни одной подстраницы.
- «Система» остаётся подстраницей «Устройства»: домашний экран, запуск, пробуждение, AirPlay — это поведение устройства, а не интерфейса.
- «Лицензии» живут только в «О системе»; версия — только там; «Обновления» показывают каталог и действие, без дублирующей версии.
- Мастер настройки доступен из «О системе» как обслуживание, а не из «Главной».

## 6. Быстрые настройки и поиск: границы

- **Control Center** остаётся фиксированным по составу. Конфигурация «состав/порядок плиток» не вводится: это новая функция, а не унификация, и она создаст настройку без спроса. Если владелец захочет — отдельный этап.
- **Поиск** остаётся локальным (приложения лаунчера, папки, скрытые). Историй, подсказок и голосового поиска в настройках нет, потому что нет и самой функции; строки-заглушки не добавляются.
- **D-pad/навигация** не получает настроек: раскладка детерминирована, менять поведение стрелок пользователю нечем и незачем.

---

## 7. Что не делаем (осознанно)

| Пункт мастер-задачи | Решение | Причина |
|---|---|---|
| Темы, цветовые схемы, обои, прозрачность, размытие | Не вводим | Отклонено владельцем ранее; текущая тёмная система едина |
| Масштаб интерфейса | Не вводим | Адаптация должна быть автоматической, а не ручной галочкой |
| Конфигурация Control Center | Отложено | Новая функция, не входит в унификацию |
| История/источники поиска, голос | Отложено | Функции нет; имитация запрещена |
| Настройка D-pad | Не вводим | Нет реальных альтернатив поведения |
| 4K-стриминг заставки | Не заявляем | Источник 1080p; честная подпись «до 1080p» вместо ложного 4K |

---

## 8. Критерии готовности архитектуры

- Каждая существующая функция имеет ровно одно основное место (таблица маппинга в документе 03).
- Ни один пункт не потерян при перегруппировке.
- Нет новых пунктов без реализации.
- Все поверхности подчиняются контрактам §3–§4.
- RU/EN-названия разделов проверены носителем (владельцем) до реализации.
