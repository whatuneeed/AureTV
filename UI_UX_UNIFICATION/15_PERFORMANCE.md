# 15 — Производительность после UI/UX-унификации

Дата: 11.11.2026. Версия: `0.4.41` (vc61). Сравнение — с `0.4.34` (vc54), последним релизом до UI/UX-этапов 3–8. Все числа — `MEASURED` на headless-эмуляторе `hume-tv`; это не результат для реального ТВ.

## 1. Стенд и метод

- AOSP TV on x86, Android 14 (API 34), 1920×1080 · 320 dpi · 60 Гц, SwiftShader, heap limit 192 МБ, `isLowRamDevice=false` → профиль **BALANCED**, тепловой статус 0.
- Оба релиза ставились чисто (`adb install`, данные очищены), мастер первой настройки пройден одним и тем же сценарием; перед замерами — 60 с на dexopt/Baseline Profile.
- Cold start: `am force-stop` → пауза 4 с → `am start -W -n …/.MainActivity`, 5 запусков.
- Warm start: HOME → `am start -W`, 5 запусков. На момент замера оба релиза не были домашним лаунчером по умолчанию (в системе установлен Java-лаунчер), поэтому HOME уводил из Kotlin, а старт был реальным resume. После назначения Kotlin домашним (`cmd package set-home-activity`) этот метод перестаёт работать: HOME возвращает уже открытую задачу (`TotalTime: 0`).
- PSS: `dumpsys meminfo` после 30 с покоя; trim — `am send-trim-memory … RUNNING_LOW`.
- Кадры: `dumpsys gfxinfo … reset`, 20 нажатий D-pad Right с шагом 150 мс. GPU-перцентили эмулятора недостоверны — сравниваются только счётчики кадров и Slow UI thread на одном стенде.

| 20× Right: кадров / janky | 66 / 27 (40,9 %) | **68 / 19 (27,9 %)** | −13 п.п. |

Разброс cold start (259–293 мс) шире разницы медиан (+5 мс), поэтому 0.4.41 **не медленнее** базы в пределах шума; warm +7 мс — тоже внутри разброса, но ближе к его верхней границе. PSS не превышал базу ни в одном срезе. Меньшая реакция на trim у 0.4.41 объяснима: в 0.4.34 в памяти висел полноэкранно растянутый баннер фокуса (дефект UX-19), у 0.4.41 такого слоя нет.

## 4. Бюджет баннера после этапа 8

- `AppRepository.loadShelfBanner` декодирует баннер только сфокусированного приложения, на IO, в размер источника, не больше коробки 1920×1080 (`fitInside`, апскейла нет).
- Крупнейший баннер в системе — мастер 640×360; ARGB_8888 ≈ 640×360×4 = **921 600 B (0,9 МБ)**; дискового кэша нет, живёт один битмап на фокус.
- Попиксельного полноэкранного слоя у 0.4.41 нет, если баннер меньше экрана более чем в 2× (`bannerIsHero`), поэтому PSS на Главной не вырос относительно 0.4.34.
