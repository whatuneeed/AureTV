## 2. Что изменено

1. **Мастер баннера.** `drawable-nodpi/tv_banner.png` заменён на 640×360, 87 448 B, SHA-256 `c5ba4f…1a821eb` — оригинал из Java-версии 1.1.17. `nodpi` сохранён: файл попадает в системный слот 640×360 px без плотностного пересчёта. Более крупного оригинала в проекте нет (`UNKNOWN`, есть ли у автора).
2. **Пайплайн баннера.** `AppRepository.drawableToImage` больше не дорисовывает изображение до 400×240: `fitInside` только вписывает в коробку и никогда не увеличивает, поэтому миниатюра сетки хранит пиксели источника. Для полки добавлен `loadShelfBanner`: баннер сфокусированного приложения декодируется один раз на IO в своём размере (коробка 1920×1080), кэша на диске нет.
3. **Правило UX-19.** `TvMetrics.bannerIsHero(widthPx, pxPerPoint)` — баннер может закрывать экран, только если экран больше него не более чем в `BANNER_MAX_UPSCALE = 2` раза. Расчёт идёт в физических пикселях панели (точки × фактор канвы × плотность), поэтому порог единый для 720p/1080p/4K: 960 px при 1080p, 1920 px при 4K. `TopShelf` рисует фон-баннер только при выполнении правила; иначе остаются обои с заголовком приложения — пустая полка по `TVOS27_RESEARCH/06_TOP_SHELF.md` §9, а не имитация арта. Загруженный постер рекомендации по-прежнему рисуется поверх и полностью закрывает экран.
4. **Бюджет.** Для всех баннеров из `14` §2 результат декодирования остался 320×180 или 640×360 — тот же, что раньше; полноэкранный декод возможен только для приложения, реально поставляющего такой баннер.
5. **Тесты.** `BannerFitTest` (4 теста, вписывание без апскейла), `TvCanvasFactorTest` +2 теста правила (1080p и 4K). Правило проверено обратным откатом: при `BANNER_MAX_UPSCALE = 3` тест падает, при 2 — зеленеет.

## 4. Заставка и 4K (UX-20)

Факты (`MEASURED`, подробнее — `14` §5): в собранном каталоге 100 клипов, все 1080p AVC; в публичном архиве Apple 63 ассета, у всех есть `url-4K-SDR`/`url-4K-HDR` (HEVC), но с каталогом пересекаются только 34 клипа. Архив отдаётся по HTTP; HTTPS не отвечает. 4K HEVC на эмуляторе не воспроизводится: AVD отдаёт 1080p, `wm size 3840x2160` телевизионный образ отклоняет.

Решение: **UX-20 в этой итерации не реализован.** Подставить 4K-URL вслепую — значит на приставках без HEVC-4K и на медленных каналах (40–80 Мбит/с) получить чёрный экран вместо заставки, и проверить это нечем. Честный путь, когда появится реальный 4K-ТВ:

1. Замерить на панели: поддерживаемый режим `Display`, HEVC-4K в `MediaCodecList`, реальную пропускную способность; память под декод 3840 (ранее измерено +35 МБ).
2. Хранить в каталоге оба URL и выбирать 4K только при подтверждённой возможности устройства, по умолчанию — 1080p AVC.
3. При ошибке плеера или таймауте переключаться на 1080p AVC того же клипа; превью и стоп-кадр не менять.
4. Повторить замеры памяти и первого кадра (этап 9), только потом считать функцию поставленной.
